## 1. General description

- **Intended purpose, users and limits:** see `instructions-for-use.md`.
- **Classification:** see `classification.md` (legal review pending).
- **Provider:** the Certivity team. The system integrates Anthropic's large language models through the official Anthropic Python SDK.
- **Forms of use:** command line (`certivity`), FastAPI service and web UI, one Docker image.

## 2. Design and architecture

The design is specified in `docs/design/compliance-pipeline-design.md`; how the agents are built is in `ENGINEERING.md`.

- A Python orchestrator runs a fixed order of steps: product analysis, scope narrowing, candidate collection, obligation extraction, matching, assembly with citation check and output audit, markets, validation and export. No language model decides the order.
- Every producing agent is checked by a code gate (schema, ids, quotes) and a verifier agent in a bounded loop; unresolved disagreement becomes *uncertain*.
- Regulation text is parsed once, page by page, into SQLite with full-text search; agents read it only through read-only tools.
- Every run writes a manifest, a hash-chained decision ledger with the full content of every call, the lineage of every requirement, and a provenance sidecar for the export.

## 4. Data

- **Corpus:** the 56 UN Regulations of the challenge index, base and latest versions, as text rendered from the PDFs. Checksums of the index and of every text file are in each manifest.
- **Training:** none. The models are used as provided; nothing is trained on customer data.
- **Evaluation data:** the worked example's expected answer is used only to score finished runs. A unit test checks that no expected requirement text appears in any agent instruction or example.
- **Personal data:** none needed or requested.

## 7. Record-keeping

Run folders under `data/runs/` hold the manifest, the ledger (`ledger.jsonl`, `calls/`), lineage, trace, report and exports. They are kept at least `CERTIVITY_RETENTION_DAYS` (default 183 days) and never deleted automatically before that. `certivity verify <run>` checks the ledger's hash chain and reproduces the submission from it.

## 8. Changes

A change to a prompt or a model changes the prompt versions in the manifest and must not lower the `bench` scores before release. Releases are tagged in git; every manifest records the git commit.
